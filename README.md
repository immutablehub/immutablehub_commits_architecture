# immutablehub_commits_architecture
ARCHITECTURE OF GIT COMMITS ON IMMUTABLEHUB



> Immutable is fully compatible with standard Git workflows. Developers continue using git commit exactly as they do today ,no new commands, no protocol changes, and no workflow migration required. Immutable integrates seamlessly into existing repositories without disrupting how teams already build and collaborate.


> All user commits are packaged and uploaded to Immutable as Git bundles, preserving the complete commit graph and repository state. Once uploaded, these commits become immutable and decentralized guaranteeing permanent availability, cryptographic integrity, and resistance to tampering, takedowns, or centralized failure. Repositories can be cloned at any time with absolute confidence in their authenticity.

> We are introducing immutable rollback history, enabling users to restore their repository to any previous commit across the entire timeline ,starting from the initial upload. Rollbacks are performed against an immutable, decentralized source of truth, ensuring historical states remain verifiable, untampered, and permanently preserved while giving developers full control over recovery and reproducibility.
